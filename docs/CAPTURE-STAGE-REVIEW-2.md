## 一、总体结论

捕获模块 **90 分，毕业**。较评审前的 85 分上了一个台阶：

- 收藏家谬误有了**双边防线**：后端（待确认门 + decay 遗忘）+
  前端（剪藏备注框、链接评论上卡——意图信号）；
- 原资料管理闭环：平台目录分类、视频只存 480p 单份、原件只增不减；
- 可观测闭环：晨报简数 + 周报详细节（含本次新增的遗忘数）；
- B站补齐了学习场景的最后一块通道拼图。

## 二、冻结建议（按严重度排序）

### 1. B站长视频护栏盲区（最重要，等痛点再动工）

`processors/link` 的 `llm_max_chars=6000` 成本护栏会让 30–60 分钟的
B站学习视频**全部跳过摘要和中图法标签**（`skipped:too-long`）——
用户最有价值的内容反而得到最少的机器帮助。

- **建议**：长视频分段摘要（切块 → 逐段摘要 → 合并），或 B站专属
  放宽上限。
- **触发条件**：用户撞到第一篇"长视频没摘要"并觉得难受时才动工。
  不提前做——短视频占多数时这是伪需求。

### 2. 确认率健康线（纯使用习惯，无代码）

当前确认率 100% **不是好事**——要么捕获太随意（什么都往里扔），
要么确认走过场（不细看点确认）。健康系统有进有出：确认率 70–90%
+ 稳定的遗忘（purge）流。

- **操作线**：每周日看周报统计——确认率连续两周 <70% → 砍通道或
  降频率；一直 100% 且从不 purge → 反思确认是否敷衍。
- 本条不改任何代码，靠用户习惯；遗忘数现已进周报统计（见第四节），
  让"删"也能被看见。

### 3. attachments 只增不减（记账，等触发）

原资料（视频 480p、截图、录音、PDF）只进不出，硬盘早晚会满。

- **建议**：做"孤儿原件清理"工具——删掉笔记已不存在、原件还躺着的
  文件（只清理，绝不碰有主文件）。
- **触发条件**：attachments >10GB，或每季度人工巡检时。已进 backlog，
  不提前做。

### 4. 周报统计加「本周遗忘数」✅ 已实施（2026-09-11）

删除也是成绩，应该可见。已落地：

- `scripts/dispatch/stats.py`：`capture_stats` 新增 `purged` 键
  （回收站 `<state_dir>/trash/` 中 ctime 落在窗口内的文件数——purge
  移入刷新 ctime；人工恢复即不再计入）；
- `render_weekly_stats` 周报社详细节新增一行：
  `- 本周遗忘（purge 进回收站）：N 条`；
- 口径仍是只读聚合，不新增任何写入面（裁决 D2 不破）；
- 测试：`tests/unit/test_dispatch/test_stats.py` 新增 4 条
  （窗口内计数 / 无回收站为 0 / 旧 ctime 排除 / 渲染行）。

## 三、维持不变（复审确认不动的）

- 微信生态通道：维持冻结，等真实导出样本；
- 截图专用文件夹"拖一步"：这是隐私代价的有意设计（不是每个截图都
  该进系统），不改自动扫描；
- 三条红线不动：零摩擦第一、机器不自动归档（人确认后才进平台目录）、
  成本护栏（捕获时刻零 API）；
- 入口分工（手机图走飞书、电脑图走专用夹、PDF 飞书发文件）是用户
  使用习惯问题，不改系统。
